## 摘要

## 主要内容

### 1. RAG 基础

- RAG（Retrieval-Augmented Generation，检索增强生成）：结合信息检索和文本生成的技术，通过实时检索相关文档作为上下文输入生成模型，提高时效性和准确性。（Page 4）
- 三大优势：解决知识时效性问题、减少模型幻觉、提升专业领域回答质量。（Page 5）
- 核心流程：Step1 数据预处理（知识库构建、文档分块、向量化）→ Step2 检索（查询处理、重排序）→ Step3 生成（上下文组装、生成回答）。（Page 6-7）
- NativeRAG 三步：Indexing（如何存知识）、Retrieval（如何找到有用片段）、Generation（如何结合提问与知识生成答案）。（Page 8）
- 即使 LLM 可以处理无限上下文，RAG 仍有意义：效率与成本、知识更新、可解释性、定制化、数据隐私五方面。（Page 36）

### 2. Embedding 模型选择

详见 [[嵌入模型 Embedding]]。HuggingFace MTEB 榜单比较了 1000 多种语言中的 100 多种文本嵌入模型（Page 11）；常用模型分四类：通用文本嵌入、中文嵌入、指令驱动与复杂任务、企业级与复杂系统（Page 12-13）。案例演示了 [[BGE-M3]] 和 gte-Qwen2 的向量编码与相似度计算（Page 14-18）。

### 3. CASE：DeepSeek + Faiss 搭建本地知识库检索

- 架构：检索（向量相似度搜索）→ 增强（检索片段作上下文）→ 生成（基于上下文和问题生成答案）；技术栈：Faiss、阿里云 DashScope text-embedding-v1、deepseek-v3、PyPDF2。（Page 22）
- 流程：PDF 逐页提取文本并记录每行页码 → RecursiveCharacterTextSplitter 分割（chunk_size=1000, chunk_overlap=200）→ DashScopeEmbeddings 向量化 → FAISS 存储（持久化 .faiss/.pkl 及页码映射）→ 相似度检索 Top-K → load_qa_chain（stuff 策略）生成 → 展示来源页码。（Page 23-30）
- LangChain 问答链四种 chain_type（stuff / map_reduce / refine / map_rerank）的原理与适用场景，详见 [[LangChain]]。（Page 33-35）

### 4. CASE：迪士尼 RAG 助手（多模态 RAG）

详见 [[多模态RAG]]。为迪士尼构建 7x24 小时在线 AI 客服：自动解答票务/入园/会员等高频问题、回答全部来自官方知识库、支持图片查询。（Page 38）

- 挑战：知识来源多样化（PDF/Word/网页/图片表格）、非结构化数据处理、知识有效组织、保证答案有效性防幻觉。（Page 39）
- 技术选型：PyMuPDF、python-docx、pytesseract（OCR）、text-embedding-v4（1024维）、[[CLIP]]（图像 Embedding，512维）、[[FAISS]] 双索引、Qwen-turbo；生产环境可用 Milvus、ChromaDB 或 Elasticsearch。（Page 40）
- 混合检索策略：文本与图像并行检索，「海报」「图片」等关键词触发图像检索；排序采用「文本优先，强制包含最佳图片」。详见 [[混合检索]]。（Page 48-49）
- 实测三个问题（退款流程、万圣节海报、年卡优惠）均能检索来源并生成回答；年卡问题回答了宝石卡/珍珠卡/翡翠卡三档价格与权益。（Page 50-55）

### 5. 切片策略

详见 [[切片策略 Chunking]]。五种方法：改进的固定长度切片、语义切片、LLM语义切片、层次切片、滑动窗口切片，并用迪士尼门票文本对比了各方法的切片结果与优缺点。（Page 56-69）

### 6. 提升 RAG 质量的三个阶段

- 数据准备：数据质量差、多模态信息提取难、复杂 PDF 解析难 → 构建完整数据准备流程（数据评估分类、清洗、敏感信息处理、标记标注、治理框架）+ 智能文档技术。（Page 72-75）
- 知识检索：内容缺失、错过排名靠前的文档 → 查询转换澄清用户意图 + [[混合检索]]和重排策略。（Page 76-78）
- 答案生成：未提取、不完整、格式错误、幻觉 → 改进提示词模板（可借助 DeepSeek-R1 推理链优化）+ [[动态防护栏]]。（Page 79-83）
- 企业实践：阿里云多粒度知识提取方案（Qwen14b + RefGPT 训练专属知识提取模型）；哈啰出行多路召回（大模型向量+传统深度模型向量，关键词、ngram 等多链路搜索召回）；中国移动 FoRAG 两阶段生成（先生成大纲再扩展成最终答案）。（Page 84）
