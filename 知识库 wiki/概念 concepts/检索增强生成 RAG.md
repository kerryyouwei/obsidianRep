# 检索增强生成 RAG

## 事实（均出自 [[RAG技术与应用]]）

### 定义

RAG（Retrieval-Augmented Generation）：检索增强生成，是一种结合信息检索（Retrieval）和文本生成（Generation）的技术。RAG 通过实时检索相关文档或信息，并将其作为上下文输入到生成模型中，从而提高生成结果的时效性和准确性。（原文 Page 4）

### 在大模型应用开发三种模式中的定位

没问清楚 → 提示工程；缺乏背景知识 → RAG；能力不足 → 微调。（原文 Page 3）

### 优势

- 解决知识时效性问题：大模型训练数据通常是静态的，RAG 可检索外部知识库实时更新信息。
- 减少模型幻觉：引入外部知识，减少模型生成虚假或不准确内容的可能性。
- 提升专业领域回答质量：结合垂直领域专业知识库，生成更具专业深度的回答。（原文 Page 5）

### 核心流程

- Step1 数据预处理：知识库构建（收集整理多源数据）、文档分块（在语义完整性与检索效率之间平衡）、向量化处理（用嵌入模型转换并存储到向量数据库）。
- Step2 检索：查询处理（问题转向量、相似度检索）、重排序（对结果按相关性排序）。
- Step3 生成：上下文组装（检索片段与用户问题结合）、生成回答。（原文 Page 6-7）
- NativeRAG 三步概括：Indexing（如何把知识存起来）→ Retrieval（如何找到一小部分有用的知识给模型参考）→ Generation（如何结合提问和检索知识生成有用答案）。（原文 Page 8）

### 与无限上下文 LLM 的关系

即使 LLM 可以处理无限上下文，RAG 仍有意义：效率与成本（减少输入长度、降低计算资源消耗）、知识更新（连接外部知识库实时增强）、可解释性（检索过程透明可查来源）、定制化（针对特定领域定制检索）、数据隐私（本地或私有数据源检索，避免敏感数据上传云端）。（原文 Page 36）

## 质量提升三阶段（原文 Page 71-84）

- 数据准备：应对数据质量差、多模态信息、复杂 PDF 提取问题 → 完整数据准备流程 + 智能文档技术。（Page 72-75）
- 知识检索：应对内容缺失、错过排名靠前的文档 → 查询转换澄清意图 + [[混合检索]]与重排。（Page 76-78）
- 答案生成：应对未提取、不完整、格式错误、幻觉 → 改进提示词模板 + [[动态防护栏]]。（Page 79-83）
